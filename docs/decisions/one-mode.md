# Plan mode and do mode are one mode

**Date:** 2026-11-23 · **Status:** decided

**Owner's words:** "Make sure that plan mode and do mode are the same thing … It assesses first
if this is going to be a significant or complex project, and only rolls back to planning if
the user remains inherently available, doesn't seem in a hurry … And the best way to find out
is just to ask: 'I can ask you a few questions before I get started. Or would you like me to
just go for it right away?'" Best first questions: "What problem are you trying to solve with
this project?" and "What would incredibly satisfy the team … with this project?"

**Decision:** No plan-first default. BeeZilla decides per request: clear or small → do it and
show proof; significant and easy to misread → one quick choice (questions, or just go), asked
once per kind of work and remembered. Questions are about the product, never the technology.

**Refined by:** [Guardrails, not specifications](guardrails-not-specifications.md) (questions are
about the why and the walls) and [Budget before going](budget-before-going.md) (the one question
that survives "just go").

**Supersedes:** the draft gate's "four Decisions Made" interview, the plan-then-confirm step and
the separate Work mode.
